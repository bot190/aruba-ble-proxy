# Aruba BLE Proxy 1.2.0

This release improves AP discovery and active BLE/GATT reliability. New APs can appear in Home Assistant without waiting for a matching BLE advertisement, and previously configured scanners are restored at startup.

## Thank you, @nunnun

Special thanks to **Hirotaka Nakajima (@nunnun)** for the contributions in [#7](https://github.com/robertoamd90/aruba-ble-proxy/pull/7) and [#8](https://github.com/robertoamd90/aruba-ble-proxy/pull/8): native Bluetooth SIG UUID encoding, improved characteristic discovery, startup scanner registration, and more stable notification sessions. These contributions are central to this release. Both PRs were merged with their original commits and authorship preserved.

## AP discovery and identification

- Register new AP scanners from the first Aruba telemetry message containing the reporter MAC, including AP health/keepalive messages. Matching BLE advertisements are no longer required for the AP itself to appear. Registration still requires an identifying message, not just an established WebSocket connection.
- Retain registration through the first BLE advertisement. Both paths use the same scanner identity and name (`Aruba AP <MAC>`), with per-AP locking to prevent duplicate creation.
- Restore previously configured AP scanners when the integration starts, before waiting for new BLE traffic.
- Report the AP hardware model from Aruba's optional `reporter.hwType` field, with `Aruba AP` as the fallback. The learned model is saved for subsequent starts. If the model arrives after scanner registration, its display may require another Home Assistant restart.

## Active BLE/GATT improvements

- Encode Bluetooth SIG UUIDs in their native 16-bit wire representation, including canonical 128-bit Bluetooth Base UUIDs and uppercase input. Vendor-specific 128-bit UUIDs retain their full representation.
- Increase the default characteristic discovery wait from 3 to 8 seconds and allow incoming characteristic bursts to settle before resolving waiting callers, reducing premature partial discovery results.
- Add debug logging for discovered GATT characteristics to help troubleshoot device compatibility.
- Keep AP notification subscriptions alive for a short grace period during rapid unsubscribe/resubscribe cycles, reducing unnecessary subscription changes and session disruption.
- Release stale connection slots when an action reports a lost BLE connection, including `notConnected` results without a separate disconnect status message.
- Cancel deferred notification-disable work during integration shutdown.

## Upgrading and validation

Update the integration and restart Home Assistant. Existing Aruba transport profiles do not need to be regenerated for these changes. BLE device discovery still depends on the configured Aruba filters; seeing an AP scanner does not by itself confirm that matching advertisements are being forwarded.

The beta was tested by the maintainer over several days with no problems reported. The automated suite passes **227 tests**. This does not extend the hardware compatibility list to additional AP models or firmware versions.
